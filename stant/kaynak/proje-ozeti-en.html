SUMMARY

Yeşil Kod (“Green Code”) finds energy-wasting patterns in Python code, rewrites the code itself, verifies that both versions return exactly the same result, and measures the energy, converting it to carbon on the Türkiye grid. In all four realistic scenarios the fix was produced by the engine; CPU energy fell by 2.4 to 4,049 times and the outputs did not change.

465×from fixing a single line, same result

01Problem

Data-centre electricity use is expected to grow from 415 TWh in 2024 to ~945 TWh in 2030 (IEA, 2025). A one-line waste inside a loop becomes a real electricity and carbon load when it runs millions of times a day, yet the energy of a line of code is measured and shown nowhere.

02Solution: four steps

1FindWithout running the code, its syntax tree (AST) is scanned and 113 waste patterns are flagged line by line.
2FixThe engine rewrites eleven patterns and touches only the changed lines; comments and formatting are kept.
3VerifyOriginal and fixed code run on the same data; if the output is not identical, the fix is rejected.
4MeasureBoth versions handle the same number of requests; CPU energy is measured and converted to carbon.

03How it is used

  • Live panel: fix, equivalence test and energy race on the stand screen.
  • Command line: analysis, fixing, measurement and reports.
  • Continuous integration: a report on every pull request; the check stops on high-severity findings.
  • Web: visitors analyse code and measure scenarios on their phone; code never leaves the device.

04Technical design

  • Python standard library only; no installation or internet needed.
  • Intel/AMD RAPL counters on Linux, Apple’s CPU power data (powermetrics) on Mac; CPU time × per-core power without permission.
  • 33 unit tests, run automatically on Python 3.9 and 3.13 with GitHub Actions on every change.

05Results

Each scenario represents a waste that is common in real projects. None of the fixed code was written by hand; the engine produced all of it and every version passed the equivalence test.

In the order report, database queries drop from 4,001 to 2; the database runs on the same machine, so network savings are not included in this ratio. At one million requests a day, the attendance line emitted about 41–89 kg CO₂e a year.

06Measurement method

  • Carbon: SCI = (E × I + M) / R. E measured energy, I Türkiye grid 341 gCO₂e/kWh (Aug 2025–Jul 2026), R per request.
  • Fairness: short code is repeated until the counters can measure it; every result is the mean of 5 repeats.
  • Caching: caches in the fixed code are cleared before every request, so gains never come from earlier runs.
  • Idle power: in hardware mode the machine’s idle power is measured and subtracted from every result.

07Honest limits

  • Only CPU energy is measured; memory, network, disk and cooling are excluded. The gain shown is a lower bound.
  • In estimated mode, ratios are more reliable than absolute values; ratios vary between machines.
  • The engine currently supports Python; it fixes eleven of the 113 patterns automatically and advises on the rest.
  • Grid carbon intensity is an annual average; the grid changes hour by hour.

08Roadmap

  • More languages: the same four-step design for JavaScript/TypeScript and Java.
  • Full SCI: include embodied hardware emissions (M) and memory energy.
  • Carbon-aware scheduling: shift heavy jobs to cleaner hours using hourly generation data from EPİAŞ (Türkiye’s energy exchange).
  • Developer tools: an editor extension and a ready-made CI step.
  • Pilot: scan student software projects at the university for waste and report the measured savings.
